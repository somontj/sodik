# sodik
# E-Commerce REST API (Интернет-магазин бэкенд)

Полноценный REST API бэкенд для интернет-магазина, разработанный на стек технологий **Java 17 / Spring Boot / JPA**. Проект реализует полный цикл работы маркетплейса: от безопасной регистрации пользователей и управления каталогом товаров до оптимизированной работы с корзиной и оформления заказов.

## 🛠 Стек технологий
* **Core:** Java 17, Spring Boot 3.x
* **Data Layer:** Spring Data JPA, Hibernate, PostgreSQL
* **Security:** Spring Security Crypto (BCrypt)
* **API & Serialization:** Spring Web (REST), Jackson
* **Validation:** Jakarta Validation API (JSR 380)

## 🚀 Ключевые фичи и архитектурные решения

### 1. Архитектура и разделение слоев (Layered Architecture)
* Полное разделение слоя хранения (JPA Entities) и слоя передачи данных клиенту с помощью **DTO (Data Transfer Objects)**. Это гарантирует инкапсуляцию бизнес-логики и исключает утечку сервисных данных (например, хэшей паролей) в API.
* Реализованы надежные **двунаправленные связи (Bi-directional relationships)** между сущностями (`Cart` <-> `CartItem`, `Order` <-> `OrderItem`) с каскадным управлением (`CascadeType.ALL`) и автоматическим удалением сиротских записей (`orphanRemoval = true`).

### 2. Производительность и оптимизация БД
* **Решение проблемы N+1:** Внедрен кастомный запрос с `JOIN FETCH` для загрузки элементов корзины вместе с продуктами за один SQL-запрос.
* **Оптимизация пакетных операций:** При одновременном добавлении списка товаров в корзину используется предварительная выгрузка сущностей через `findAllById` с последующей группировкой в `Map`. Это снижает нагрузку на БД с $O(N)$ запросов до $O(1)$.

### 3. Безопасность и Валидация
* **Хэширование паролей:** Пароли пользователей защищены с помощью алгоритма `BCryptPasswordEncoder`.
* **Защита от Timing Attacks:** Логика аутентификации спроектирована так, что проверка хэша выполняется даже для несуществующих пользователей (используя dummy-хэш), что выравнивает время ответа сервера и защищает от подбора данных по таймингам.
* **Валидация данных:** На уровне DTO и Entities настроена строгая валидация (проверка форматов Email, ограничение на длину строк, защита от отрицательной цены или отрицательного количества товара на складе).

### 4. Работа с медиа-файлами (Multipart)
* Реализован полноценный сервис загрузки изображений товаров через `MultipartFile`.
* Изображения сохраняются на сервере с генерацией уникальных имен (`UUID`), первая загруженная фотография автоматически маркируется как главная (`isMain`).
* Настроено автоматическое каскадное удаление файлов из файловой системы при удалении товара из каталога.

## 📊 Доменная модель (База данных)
* **User** — данные клиента (имя, фамилия, уникальный email, телефон, адрес, хэшированный пароль).
* **Product** — каталог товаров (название, описание, цена, категория, количество на складе, связь с картинками).
* **ImageProduct** — ссылки на фотографии товаров.
* **Cart & CartItem** — корзина пользователя, привязанная к сессии.
* **Order & OrderItem** — оформленные заказы с фиксацией стоимости на момент покупки, адресом доставки и уникальным номером заказа (генерируется в `@PrePersist`).

## 🛣 Основные API Эндпоинты

### Пользователи (`/api/users`)
* `POST /register` — Регистрация нового пользователя с валидацией полей.
* `POST /login` — Аутентификация и создание сессии (`HttpSession`).

### Каталог товаров (`/api/product`)
* `GET?category=...` — Получение списка товаров (с опциональной фильтрацией по категории).
* `POST /addProduct` — Добавление товара и загрузка файлов (поддержка `multipart/form-data`).
* `PUT /updateProduct/{id}` — Редактирование информации о товаре.
* `DELETE /deleteProduct/{id}` — Удаление товара и связанных файлов с диска.

### Корзина (`/api/cart`)
* `GET /cart` — Получение корзины текущего авторизованного пользователя с расчетом `totalPrice`.
* `POST /addItem` — Добавление одного товара.
* `POST /addItems` — Пакетное добавление списка товаров (оптимизированное).
* `PUT /changeQuantity` — Изменение количества (удаление при `quantity = 0`).

### Заказы (`/api/orders`)
* `POST /createOrder` — Оформление заказа из текущей корзины, фиксация цен, очистка корзины.
